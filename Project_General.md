# Project_General

## Назначение проекта
Проект BuildMap состоит из клиентского веб-приложения и серверной части для работы с планами корпусов, аудиториями, маршрутами и расписанием.

## Структура репозитория
- `CLIENT/` — фронтенд (React + TypeScript + Vite), рендер карты этажей, поиск, UI, маршрутизация, модальные окна, режим администратора.
- `SERVER/` — сервер API на Node.js и Python-инструменты для парсинга расписания из PDF.
- `.venv/` (в корне) — локальное Python-окружение разработки.

## Архитектура CLIENT
- `src/main.tsx`, `src/App.tsx` — вход приложения и базовая сборка UI.
- `src/app/` — прикладная логика и состояния:
  - `hooks/useBuildMapApp.ts` — главный оркестратор состояния клиента.
  - `hooks/buildmap/*` — загрузка данных, геопривязка, админ-режим, планировщик маршрутов.
  - `search/*`, `offices/*`, `utils/*` — поиск, справочник, утилиты.
- `src/map/` — визуализация плана:
  - `FloorPlanCanvas.tsx` — основной 3D/2D canvas-контейнер.
  - `canvas/*` — поведение камеры, автоподгонка, подсветка, подписи.
  - `rooms/*` — модели помещений, загрузка/нормализация, цвета, категории.
  - `floorplan/*` — конфиг освещения/эффектов и вспомогательные утилиты рендера.
- `src/navigation/` — геопроекция и движок построения маршрутов между узлами графа.
- `src/interface/` — UI-компоненты панелей, модалок и контролов.
- `src/schedule/` — доменная модель расписания и API загрузки CSV-пакетов.

## Архитектура SERVER
- `src/server.mjs` — HTTP API:
  - выдача манифестов и данных по этажам (`rooms`, `graph`, `rooms.csv`);
  - выдача расписания (`/api/schedule/*`);
  - админ-эндпоинты для сохранения правок помещений и графических пресетов.
- `schedule_parser/parser.py` — парсер PDF-расписаний в CSV с постобработкой и очисткой артефактов.
- `schedule_parser/web_worm/download_current_schedule_pdfs.py` — загрузчик актуальных PDF расписания с сайта ВятГУ.
- `schedule_parser/parsed_schedule/` — результат парсинга расписания по датам.

## Данные и артефакты
- `CLIENT/public/` содержит статические данные:
  - `build*/floor*/room_data.csv` — исходные данные помещений;
  - `build*/floor*/room_data.json` — нормализованные данные для клиента;
  - `build*/floor*/room_graph.json` — граф навигации по этажу;
  - `room_data_manifest.json` — список корпусов/этажей;
  - `build*/room_overrides.json` — пользовательские правки помещений;
  - `graphics_presets.json` — профили графики;
  - `schedule/` — локальные CSV расписания.
- `CLIENT/scripts/generate-room-json.ts|mjs` — генерация `room_data.json`, `room_graph.json`, иерархии офисов и манифеста.

## Поток работы
1. Исходные CSV планов и расписания кладутся в `CLIENT/public` и `SERVER/schedule_parser`.
2. Скрипты генерации в `CLIENT/scripts` собирают JSON-артефакты для фронтенда.
3. Сервер `SERVER/src/server.mjs` отдает данные и принимает админ-изменения.
4. Клиент `CLIENT` загружает манифест/этажи/графы, строит визуализацию и маршруты.
5. Python-парсер обновляет CSV расписания, после чего данные становятся доступны через API и статические файлы.
